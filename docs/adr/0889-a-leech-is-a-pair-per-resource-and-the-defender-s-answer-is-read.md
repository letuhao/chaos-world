# 0889 a leech is a pair per resource and the defender's answer is read

- Status: Accepted
- Date: 2026-10-06

## Context

- The completeness audit (DEF-0351): `CombatRecoil.leech` called
  `rate_from_zero(stat(LIFESTEAL), 0.0, rate_scale)` — the defence half was a literal
  `0.0`, `CombatStats.CONTESTS` did not name it, and nothing a defender built could answer
  a drain. Under AGENTS.md's yin-yang rule that is an advantage with no counterpart.
- The owner chose "ONE PAIR PER RESOURCE": explicit per-pool ids, authored like every
  other family.
- The pools that exist: core's `health` and `stamina` (`core/actor_pools.gd`) and the qi
  pool the casting layer owns (`modules/techniques/technique_casting.gd:71`).

## Decision

- `CombatStats` owns the family: `lifesteal.<pool>` against `leech_resist.<pool>`, for
  every pool in `POOLS`, generated by `leech_ids()` — so a fourth pool joins by existing.
  `ALL_IDS`, `RATE_IDS` and `RATE_DEFAULTS` list the six ids literally (a `const` cannot
  call the generator) and `test_combat_stats_shape` pins the literal lists against
  `leech_ids()`, which is the one half a generator cannot reach.
- `CONTESTS` carries the three pairs as literal entries, so `counterpart_of` answers for
  the family and the pair is data the way every other contest's is.
- `CombatRecoil.leech` takes `target` and reads the pair of `tuning.lifesteal_pool` over
  `rate_scale` — the SAME flat contest every trigger uses. The tuning names the resource;
  the contest follows it.
- The share's BASE is still what left the TARGET's health, because health is the only
  pool a blow moves today. The pair decides how much returns; the tuning's pool decides
  what it returns AS. When a mechanism spends another pool, the base can widen without
  touching this pair.
- The stat presenter lists both halves per pool, so a sheet can show what a drain is
  answered by.

## Consequences

- A leech build is answerable on the resource it drains, and the two acceptance cases are
  pinned: `test_a_defender_s_leech_resist_cancels_the_drain` (equal halves read exactly
  zero) and `test_the_drain_lands_in_the_pool_the_tuning_names` (the qi pair refills qi).
  DEF-0351 is `done`.
- A per-technique pool (a technique that drains qi while another drains health) remains a
  CONTENT decision, not a gap: the engine already reads whichever pair the tuning names,
  and a later `TechniqueDef` field would feed that same read.
- The placeholder coefficients for the family sit in DEF-0344's retune list like every
  other authored magnitude.
