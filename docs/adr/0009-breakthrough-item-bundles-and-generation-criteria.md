# 0009 Breakthrough item bundles and generation criteria

- Status: Accepted
- Date: 2026-10-01

## Context

Elemental mastery and succubus breakthroughs need items that are hard to obtain (boss fights plus crafting). Content is generated in bulk by agents, so the bundle shape and constraints must be explicit and machine-checkable.

## Decision

- Each cultivation system has one **breakthrough bundle per realm tier** (Mortal, Spirit, Immortal, Transcendent): four bundles per system.
- A bundle is a self-contained acquisition chain:
  - one breakthrough consumable (category `consumable`, subtype `pill`/`elixir`), source `craft:<recipe>`;
  - two or more materials, at least one `gather` and at least one `boss:<boss>`;
  - one recipe (station `alchemy`), inputs = the bundle materials, outputs = the breakthrough item;
  - one boss with `domain_id` = the bundle domain and `loot` including the boss material;
  - one domain whose `boss_ids` includes the boss.
- Ids: `<system>_<tier>_<kind>` (e.g. `elemental_mortal_breakthrough_pill`, `succubus_spirit_core`). The `<system>` prefix namespaces the bundle; a bundle must not reference another system's ids.
- Grades: Mortal -> `mortal`, Spirit -> `spirit`, Immortal -> `immortal`, Transcendent -> `divine` (ADR 0007 mapping).
- Hard to obtain: the breakthrough item is craft-only, at least one material is boss-only, and the boss lives in a domain.
- Constraints: English; clinical, non-sexual naming; pure gameplay mechanics.
- Generation: create `.tres` with `uv run python -m tools data new`; validate with `uv run python -m tools data audit` (must be clean). The audit is the acceptance test.
- Content is generated by background sub-agents, one per system, writing only under `game/data/`.

## Consequences

- Bulk content is consistent and validated by the tool.
- Every breakthrough item has a reachable chain: domain -> boss -> material -> recipe -> item.
- Extending bundles (more items or ranks) is additive; the audit catches dangling references.
