# 0880 the element crit pair is read through the technique's own element

- Status: Accepted
- Date: 2026-10-06

## Context

- ADR 0215 shipped the per-element crit pair (`element_crit_<e>` /
  `element_crit_resist_<e>`, plus the omni ids `element_crit_` / `element_crit_resist_`):
  generated by prefix from the element table, both halves together, provider-emitted and
  realm-scaled. S3's trigger read only the core `Stat.CRIT_CHANCE` / `Stat.CRIT_RESIST`
  pair, so the channels had NO reader.
- Keepverse's resolver sums omni + element per component. Ours cannot copy that shape:
  `ElementProvider` makes the omni channel the same formula over the SUMMED affinities
  and masteries, so omni + element would count the technique's own element — and the
  `CRIT_BASE` every channel already carries — twice.

## Decision

- S3 reads `CRIT_CHANCE + element_crit_<channel>` against
  `CRIT_RESIST + element_crit_resist_<channel>`, through `CombatStats.rate_from_zero`
  (ADR 0877's flat rule). Equal halves cancel to `0.0`.
- The channel is the technique's own element (`TechniqueDef.element`); an elementless
  technique reads the omni ids (empty suffix). ONE technique reads ONE channel.
- `CombatTuning` gains `element_crit_prefix` / `element_crit_resist_prefix` as authored
  STRINGS, the same shape as `element_power_prefix`: a `StringName` constant naming
  `elements` would put a compile-time edge into a module whose dependency list is
  `["contracts", "core"]`, and the registry must not lie. Both must be authored for the
  channel to be read; a tuning without them behaves exactly as before.
- The provider's coefficients (`CRIT_BASE 0.05`, affinity/mastery/will steps) stay where
  they are — this ADR only makes them READ.

## Consequences

- The element crit pair is live: an elemental technique's crit chance moves with the
  attacker's affinity/mastery and the defender's matching resist and will.
- `rate_scale` prices the element channels and the core pair on the same exchange rate,
  so one retune moves both (wave 2's balance pass owns the value).
- Tests: `tests/modules/combat_engine/test_element_crit_wiring.gd` pins the element
  channel, the no-leak rule, the parity cancellation, the omni fallback, the unknown
  element read and the prefix gate; `tests/modules/elements/test_element_crit_channels.gd`
  keeps pinning the generation.
